# FE-03 · 고객 링크 접속·동의·방문정보

2026-10-29 기준. QR을 제외하고 기존 Figma의 고객 화면을 구현한다. 실제 문의 생성·방문정보 저장은 FE-08, 문자 인증·복구는 FE-20에서 연결한다.

## 화면 확인

로컬 실행 환경에 `CUSTOMER_PREVIEW_ENABLED=true`를 설정한 뒤 `/customer/preview`에서 확인한다. 기본값은 꺼짐이며, 꺼져 있으면 확인용 경로는 404다. 테스트 데이터와 입력값은 메모리에만 있으며 새로고침하면 사라진다. API·문자·지도·AI는 호출하지 않는다. 실제 고객 정보를 입력하지 않는다.

| 주소 뒤에 붙일 값    | 확인 내용                                                                        |
| -------------------- | -------------------------------------------------------------------------------- |
| 없음                 | 업체 확인 → 필수·선택 동의 → 상담 연결 지점 → 방문정보 입력 → 입력내용 확인·수정 |
| `?state=invalid`     | 폐기·유효하지 않은 링크                                                          |
| `?state=paused`      | 신규 접수 중지·기존 예약 조회 연결 지점                                          |
| `?state=unavailable` | 이용 불가 업체                                                                   |
| `?state=loading`     | 업체 확인 중                                                                     |
| `?state=error`       | 연결 실패·다시 불러오기                                                          |
| `?fail=start`        | 상담 시작 실패·동의 유지                                                         |
| `?fail=visit`        | 방문정보 전송 실패·입력 유지                                                     |
| `?fail=address`      | 주소 확인 실패·항목별 안내                                                       |
| `?fail=region`       | 서비스 지역 밖 안내                                                              |

채팅 부분은 FE-05 연결 지점으로 명시한다. 확인용 화면에서만 ‘방문정보 화면 확인’으로 건너갈 수 있다. 실제 운영 상담이 진행되거나 접수가 완료됐다고 표시하지 않는다. 일반 `/customer`는 업체 링크로 접속할 것을 안내하며, 확인용 옵션이 꺼진 환경에는 예시 업체나 확인용 링크를 표시하지 않는다.

## 구현 범위·연결 지점

- `CustomerIntake`의 `business`는 화면 내부 모델이며 실제 API 응답 필드로 확정한 DTO가 아니다.
- `status`로 업체 확인 중·유효하지 않은 링크·접수 중지·이용 불가·통신 실패를 구분한다. 확인용 옵션이 꺼진 일반 환경에서 `preview`를 주지 않는다.
- `onStart({ consents })`: 필수 `PRIVACY_REQUIRED`와 고객이 선택한 `PHOTO`, 업체에서 받은 약관 버전을 전달한다. FE-08에서 API 명세의 `POST /api/v1/public/intake/{linkToken}/inquiries`를 연결하고 성공 후 FE-05로 이동한다. 콜백이 없으면 버튼을 비활성화한다.
- `initialStep="visit"`: 기존 문의에 접근 가능하고 필수 동의가 확인된 상태에서 상위 연결 화면이 사용한다. `onSaveVisit(VisitInfo)`에서 명세의 `PUT /api/v1/customer/inquiries/{inquiryId}/visit-info`를 연결한다. 성공 후 접수 확인 화면으로 이동하는 것은 상위 콜백의 책임이다. 콜백이 없으면 저장 버튼을 비활성화한다.
- 연락처는 미인증 상태로 표시한다. 문의 토큰 저장·전달 방식을 새로 정하지 않으며, 기존 공통 `requestApi`를 FE-08에서 재사용한다. 고객정보를 URL·브라우저 저장소에 넣지 않는다.
- 작업 유형·추가 요청·상세 주소는 선택 입력이다. 사진·모델명·오류코드 입력을 방문정보 필수 조건으로 추가하지 않는다. 이름·번호 형식·기본주소를 항목별로 검사한다.
- 주소의 존재·방문 가능 지역은 서버가 확인한다. 화면의 형식 검사를 지역 검증 성공으로 표시하지 않는다. 서버의 항목별 오류를 FE-08에서 이 화면에 매핑해야 한다.
- 같은 입력 화면 안에서 뒤로 가기·수정·전송 실패 시 입력을 유지한다. 다시 전송 중 중복 실행을 막는다. 새로고침·창 닫기 이후 복구는 FE-20 범위다.

## QR 조사

QR은 접수 URL의 다른 표현이다. 명함·인쇄물·제품 스티커를 스캔해 접속할 때 쓸 수 있지만, 문자·메신저로 접수 링크를 받은 고객에게는 링크만으로 같은 접수를 제공할 수 있다. QR 자체가 업체 식별이나 고객 인증을 추가로 제공하지는 않는다.

기능명세 전체 60개 항목의 속성과 관련 원문을 확인했다. QR 직접 언급은 다음 3개 기능이다.

| 기능                                                            | 현재 내용                               |
| --------------------------------------------------------------- | --------------------------------------- |
| [C-01](https://app.notion.com/3e824a392ba98193b8cbd3684fe1a290) | 고객이 업체 링크 또는 QR로 접속         |
| [B-11](https://app.notion.com/3e824a392ba9813c86e0facadcec54f2) | 사장님이 링크 복사·공유 및 QR 조회·저장 |
| [O-04](https://app.notion.com/3e824a392ba981429f19e448fca2093f) | 운영이 업체 링크·QR 발급                |

WBS 속성에서 QR 직접 언급은 [BE-04](https://app.notion.com/3e824a392ba981e2a5b2d065e1dc8029)(박준형, 링크·QR 생성·유효성 확인)와 [FE-06](https://app.notion.com/3e824a392ba981239df4c8081eaaf2af)(유승, 사장님 홈에서 공유) 2개다. 위 3개 기능과 관련 기능 속성으로 연결된 WBS는 BE-04·BE-05·FE-03·FE-06·FE-08·FE-09·FE-19·FE-21·QA-01의 9개다. 이 9개 전체가 QR 전용 업무라는 뜻은 아니며 접수·공유·운영·테스트 범위가 함께 묶여 있다. FE-03은 C-01을 통해 연결되지만 QR 생성·스캔기를 직접 구현하는 작업은 아니다.

정책서의 접속 경로, 테스트 기준서의 TC-C01-N·TC-B11-N·TC-O04-N에도 QR이 나온다. API 명세는 사장님 `GET /api/v1/owner/intake-link`에서 주소·상태를 받고 QR은 화면에서 생성한다고 설명한다. WBS의 ‘링크·QR 발급 API’ 표현과 생성 책임이 다르다.

이번 결정은 **FE-03에서 QR을 구현하지 않고 링크 접속 화면을 진행**하는 것이다. QR의 영구 삭제나 다른 담당자 범위 변경을 결정하지 않았으며 명세·다른 담당자의 WBS·테스트 항목을 삭제하지 않는다. 추후 QR을 제외하기로 확정하면 위 3개 기능·2개 WBS·정책서·관련 테스트·화면의 QR 문구를 링크 중심으로 함께 바꾸면 된다.
