# FE-05 · 고객 상담·사진·접수정보 화면

## 구현 범위

기존 Figma C02(2031:220)·C03(2031:260)·C05(2031:329)를 Next.js·CSS Modules로 연결한다. 흰 배경, Noto Sans KR, 주황 주요 동작, 44px 보조 동작, 52px 주요 동작을 유지한다. 가짜 휴대폰 상태바는 만들지 않는다.

- 고객·덕구·사장님 메시지와 전송 중·실패 상태
- 사진 동의 확인, JPG/PNG·문의당 10장·장당 10,000,000바이트 제한, 디코딩 실패 안내
- 첨부 취소·사진별 업로드 실패·재시도, 성공한 사진 재업로드 방지
- 업로드 후 메시지 실패 시에도 첨부를 취소할 수 있다. 이는 전송 전 메시지에서 제외하는 동작이며 원격 파일 삭제 완료를 뜻하지 않는다. 미연결 업로드 정리는 BE-06 연결 때 확인한다.
- 메시지 재전송 시 같은 clientMsgId 유지, 진행 중 중복 전송 차단
- 모델명 촬영 가이드, 참고정보 미확인 상태로 계속 진행
- 항목별 고객 설명·사진 확인·사장님 확인·매뉴얼 해석 및 충돌 구분
- 직접 상담 요청은 콜백 성공 후에만 상위 연결 화면에서 응대 주체를 변경
- 방문정보 입력·접수 확인·수정 연결; 입력·사진은 기기 메모리에서만 관리

## 화면 확인

`CUSTOMER_PREVIEW_ENABLED=true` 환경의 `/customer/consultation-preview`. 기본 비활성 상태는 404다. 외부 API·AI·문자·지도·실제 저장을 호출하지 않는다. 상단에 고정 응답·예시 데이터임을 표시한다.

| 옵션                       | 확인 내용                                     |
| -------------------------- | --------------------------------------------- |
| 없음                       | FE-03 접속·동의 → 상담 → 방문정보 → 접수 확인 |
| `?scene=chat`              | 빈 상담 화면                                  |
| `?scene=retake`            | 피그마 예시 대화·사진·미확인 모델명·촬영 안내 |
| `?scene=summary`           | 접수 확인 예시                                |
| `?scene=chat&fail=send`    | 첫 메시지 전송 실패 후 재전송                 |
| `?scene=chat&fail=upload`  | 첫 사진 업로드 실패 후 재전송                 |
| `?scene=chat&fail=handoff` | 직접 상담 요청 실패 후 재시도                 |
| `?scene=chat&fail=expired` | 접근 만료 안내·작성 내용 보존                 |

사진은 실제 파일을 선택해 로컬에서 확인한다. 사진 분석값은 고정된 Figma 예시에만 있으며 임의 첨부 사진에서 분석 결과를 만들어내지 않는다. 복구 인증·예약시간 선택은 FE-20·FE-11의 후속 연결 범위다.

### 11/2 휴대폰 HTTP 접속 보완

같은 Wi-Fi의 HTTP 주소는 localhost와 달리 `crypto.randomUUID`를 제공하지 않아 메시지 전송·사진 첨부·직접 상담이 실패했다. 공통 `createClientId`에서 `crypto.getRandomValues` 기반 UUID v4를 지원하고, 메시지 ID 생성도 오류 처리 범위 안으로 옮겼다. 인증·권한 토큰을 생성하는 기능은 아니다.

단위 테스트 39개와 운영용 빌드를 통과했다. 실제 LAN HTTP 주소의 모바일 브라우저 검사에서 메시지·사진 전송, 직접 상담, 방문정보 확인·수정과 입력 보존을 확인했고 페이지 오류는 없었다. `randomUUID`가 없는 조건을 기존 상담 브라우저 회귀 검사에도 추가했다. 실제 휴대폰의 키보드·사진 선택 UI는 사용자 재확인 후 완료를 판단한다.

### 갤럭시 S23 · 삼성 인터넷 실기기 확인

USB로 연결된 갤럭시 S23의 삼성 인터넷 30에서 동일한 HTTP 미리보기를 직접 검증했다. 키보드가 열린 상태에서 `innerHeight`는 791px이지만 실제 보이는 영역(`visualViewport.height`)은 약 415px로 줄어들어 기존 상담 입력창이 가려졌다. 상담 화면이 보이는 영역 높이에 맞춰 조절되도록 수정했다. 미리보기 안내 높이는 고정 56px 대신 실제 화면 위치로 반영한다.

수정 후 메시지 입력·전송 버튼의 하단은 약 387px로, 키보드 위의 보이는 영역 안에 유지됐다. 메시지 전송, 테스트 사진 첨부·취소·재첨부·전송, 방문정보 입력→접수 확인→수정·입력 보존을 실기기에서 확인했고 페이지 오류는 없었다. 사진은 프로젝트의 합성 예시를 사용했고 개인 갤러리는 사용하지 않았다. 자동 검사는 단위 테스트 39개, 상담 브라우저 검사 11개 묶음과 운영용 빌드를 통과했다. FE-05 PR 검토·병합 및 FE-08 실제 서버 연결은 별도 후속이다.

## FE-08 실제 연결 준비

`src/lib/customer-api.ts`는 기존 requestApi를 재사용한다. 명세 v0.3에 요청·응답 예시가 있는 상담 생성·메시지 전송만 구현하고 응답을 검사한다. 프리뷰에서는 호출하지 않는다.

| 연결 지점     | 서버 계약                                                              | 준비 상태                                              |
| ------------- | ---------------------------------------------------------------------- | ------------------------------------------------------ |
| 상담 시작     | POST `/public/intake/{linkToken}/inquiries`, 필수·선택 동의 및 버전    | 요청·응답 검사·테스트 준비                             |
| 메시지 전송   | POST `/customer/inquiries/{id}/messages`, clientMsgId·content·photoIds | 요청·응답 검사·테스트 준비                             |
| 사진 업로드   | 업로드 시작 → 저장소 전송 → complete 성공 후 photoId                   | 콜백 준비; 업로드 ticket DTO·허용 헤더 확인 필요       |
| 상담 갱신     | 메시지 조회·문의 상태·fields, afterId 및 취소 신호                     | 메시지/필드 DTO·권한 만료 응답 확인 후 2초 폴링 연결   |
| 방문정보 저장 | PUT visit-info, 서버 주소·지역 검증                                    | FE-03 콜백 재사용; 최종 DTO·항목별 오류 매핑 확인 필요 |
| 직접 상담     | POST handoff-requests                                                  | 콜백 준비; 성공·실패·중복 결과 DTO 확인 필요           |

문의 토큰은 URL·브라우저 저장소에 쓰지 않고 Authorization 헤더로 전달한다. AI 결과의 최신 버전·필수정보·이관 여부는 Spring이 검증한다. 프론트가 임의의 메시지 내용이나 모델명 누락만으로 예약 가능·이관 상태를 결정하지 않는다.

실제 연결 검증은 BE-04/05/06/08과 서비스용 FastAPI 경로 준비 후 진행한다. UI·목업 검사와 실제 고객 접수 저장 완료는 구분한다.

### FE-08 방문정보 저장 준비

- 로컬 BE-05에서 같은 문의의 버전을 조회하고 방문정보를 저장·재조회한다. 오래된 버전은 409로 거절되며 자동 재전송으로 덮어쓰지 않는다.
- 11일 시연은 개발 환경의 전용 테스트 업체 링크에만 연다. `CUSTOMER_LIVE_ENABLED=true`, `CUSTOMER_VISIT_DEMO_LINK_TOKEN=<테스트 업체 링크 토큰>`을 설정하고 API는 `https://dev-api.illo.ai.kr` 또는 로컬 루프백을 사용한다. 일반 업체 링크는 그대로다.
- 출발지는 이레엔지니어링([화전동 229-56, 도로명 화랑로 1](https://dorojuso.kr/4128112900102290056016664)), 방문지는 [한국항공대학교 항공대학로 76](https://nalda.kau.ac.kr/business/map.php)이다. 기존 방문정보 API에는 항공대 주소·좌표와 시연용 이름·연락처만 저장한다. 출발지, GPS, 실시간 이동시간, 예약 확정은 이 화면의 처리 범위가 아니다.
- `/customer/consultation-preview?fail=visit`에서는 첫 저장을 실패시켜 입력 보존과 재시도를 확인한다. 이 화면은 실제 서버에 저장하지 않는다.
- 실제 고객 화면에서 방문정보 저장을 열기 전, 기본주소에 대응하는 좌표를 서버에서 받을 수 있어야 하며 첫 동의에 이름·연락처·방문주소 수집 범위가 포함돼야 한다. 주소 조회에 상세주소·연락처를 보내거나, 실패한 주소에 임의 좌표를 붙이지 않는다.

### FE-08 사진 연동 검증

- `CUSTOMER_PHOTO_DEMO_ENABLED=true`인 전용 Dev 시연 링크에서만 별도 사진 동의와 첨부를 표시한다. 기본값은 비활성화다. `POST photos` → S3 `PUT` → `complete`에서 `DONE` 확인 → 메시지 `photoIds` 순서다.
- 완료 응답이 끊기면 같은 사진 ID로 완료만 다시 확인한다. 아직 업로드를 시작하지 않은 첨부는 화면에서 제거한다. 서버가 업로드 ID를 발급한 미전송 사진은 `DELETE /api/v1/customer/inquiries/{id}/photos/{photoId}`로 취소한다. 취소 실패 시 사진과 기존 재전송 상태를 유지한다. 공유 Dev에서 DELETE를 제공하고 권한·취소·재전송을 확인하기 전까지 사진 기능은 꺼 둔다.
- Dev API 검증: 시연용 문의 #3에서 합성 보일러 예시 사진 1장으로 S3의 Dev 출처 허용, 저장, 완료 확인, 사진만 보낸 메시지 저장·재조회를 확인했다. 공유 Dev 화면 캡처, 원본 다시 보기, AI 추출은 이 결과에 포함하지 않는다.

## Direction contract

THESIS: 고객이 사진과 짧은 설명을 보내고 필요한 항목만 확인하는 기존 고객 흐름을 확장한다. 새 대시보드나 장식 카드를 만들지 않는다.

OWN-WORLD: 기존 흰 바탕·회색 대화 말풍선·주황 주요 동작·Noto Sans KR·44/52px 동작과 로컬 Figma 자산을 유지한다.

STORY: 증상 설명 → 필요한 경우 사진 보완 → 출처가 구분된 접수 정보 → 방문정보 확인. 사진·모델명은 보편 필수가 아니다.

FIRST VIEWPORT: 390px 모바일, 상단 56px 제목·접수 버튼, 중앙 대화, 하단 첨부·메시지 입력. 촬영 가이드는 그림과 라벨 예시를 나란히 놓고 주요 동작을 하단에 둔다.

FORM: 사용자 기존 Figma 지정 구성의 기능 확장. 컨셉 추첨·새 시안 생성 없이 C02/C03/C05를 기준으로 한다. 고정 대화·사진은 확인용으로 표시한다.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
