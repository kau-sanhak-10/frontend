# 화면·목업 운영 기준 · 2026-10-26

원본: [정책서](https://app.notion.com/p/3f424a392ba98119a45ff7a5561f87dd),
[API 명세](https://app.notion.com/p/abb24a392ba982e385f6818e70436b3e),
[Figma 화면](https://www.figma.com/design/HOqnylvpN0CFRzcywqnLRR/?node-id=2003-28).

- OTP 300초·재발송 60초·입력 5회, 사장님 세션 7일. 목업은 이 값만 재현한다.
- 번호별 최근 1시간 5회·24시간 10회, IP별 최근 1시간 30회는 서버에서 누적 제한한다.
  목업의 메모리 이력·브라우저 세션 값은 실제 접근 통제나 보안 장치가 아니다.
- 고객 세션 24시간·운영 세션 12시간은 각각 실제 서버 응답의 만료를 따른다.
- 변경 제안은 기존/제안 시간·주소와 서버 만료 시각을 함께 보여준다.
  만료는 생성+24시간과 제안 방문 시작−2시간 중 먼저이며 수락·적용 전에는 기존 예약을 유지한다.
- 수동 예약의 영업시간 밖 경고는 별도 확인 후 허용하되 겹침·이동 불가·필수정보 누락은 차단한다.
- 사진은 문의당 10장·장당 10,000,000바이트·JPG/PNG. HEIC 지원 표시는 검증 후 추가한다.
- 승인 대기의 운영 문의와 로그인 번호 변경을 구분한다. 완료 정정은 사유와 이력을 남긴다.
- 미등록·미승인·미연결·이용 제한 계정은 인증번호 발송 전에 안내한다. 인증 완료라고 표시하지 않는다.
- 작업별 참고정보만 미확인이면 값만 표시하고 상담·예약을 계속한다. 이 사유만으로
  확인 필요 건수·사장님 업무·알림·OWNER_CHECK를 만들지 않는다. 필수정보 미해결·안전·직접 상담 요청은 기존 이관 기준을 따른다.
- AI는 예약 단계로 이동할지와 다음 행동을 반환한다. 프론트가 Spring의 가능시간을 조회하고
  고객 선택·최종 확인 후 예약 API를 호출한다. Spring이 권한·인증·최신 일정·중복을 검증해 저장한다.
- 모델 호출 기반은 Bedrock으로 맞춘다. 이미지 입력 지원 멀티모달 모델과 별도 실행 환경의
  YOLO+OCR+룰은 같은 출력·평가 기준으로 계속 개선한다. 매 사진을 두 경로에 중복 실행하지 않는다.
  구체 모델·리전·접근 권한·비용은 실제 호출 검증으로 확정한다.
- 카카오톡 연결은 MVP 이후 범위이며 현재는 웹 문의 링크를 사용한다.

사진·예약·운영 화면의 실제 구현은 해당 WBS에서 진행한다. 문서·Figma 반영을 구현 완료로 집계하지 않는다.
